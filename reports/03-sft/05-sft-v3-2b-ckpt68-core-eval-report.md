## 4. 综合诊断与下一步判断

1. **强泛化证实：`sft_v3` 学到的是可迁移的 Schema/调用结构能力，而非过拟合 9 类快筛集**
   - 独立未参评 8 类的整体增益（**`+6.06 pp`**）与参评 9 类（`+6.68 pp`）几乎一致；
   - **`simple_java`（+45.00 pp）与 `simple_javascript`（+16.00 pp）** 在训练数据以 Python/REST 为主、且未参与任何选优的情况下大幅跃升，推动 `Non-Live AST` 整体突破 **`82.25%`**；
   - **真实场景 `Live` 全部调用子类全面提升**：`live_simple` (+12.79 pp)、`live_multiple` (+1.61 pp)、`live_parallel` (+6.25 pp)、`live_parallel_multiple` (+37.50 pp)。

2. **暴露出的三条真实边界（指导下一步 RL / 数据迭代）**
   - **长上下文多轮（`multi_turn_long_context`: `24.00%` vs 基座 `28.00%`）与 `multi_turn_miss_func`（`1.00%`）仍是核心短板**：其中 `multi_turn_long_context` 贡献了本次全量全部 `5` 次超 64K 拒绝和 `46/54` 次 1024 输出截断，大量错在长历史下的状态不一致（83）与执行返回值漏报（46）；这主要是 `sft_v3`（≤7.5K token）未覆盖超长上下文状态追踪所致。
   - **拒绝/调用边界略低于基座 1 个百分点**：`irrelevance`（77.50% vs 78.75%）、`live_irrelevance`（67.76% vs 68.67%）、`live_relevance`（81.25% vs 87.50%）略低于基座，但仍在门槛线之上且未滑入 `ckpt-102..168` 的零调用塌方区间。
   - **API-Bank 回包泄漏（`128/528`）与 `L3 missing_tool_call`（20 次）**：`L3` 未发生 1 次长串步骤全对（`L3_dialogues_all_steps_correct = 0`，单步准确率 57.14%），且在多轮中间步骤（`tool_choice="none"`）的纯文本收尾习惯仍需强化。

3. **阶段推进结论**：
   - **`SFT-v3 checkpoint-68` 完全合格作为当前阶段的 SFT 正式产出基线与 Stage 2（OPD / GRPO）初始化策略权重**（BFCL Core 加权分 `43.48% -> 47.02%`，全量微平均 `59.27% -> 65.71%`，API-Bank `66.53% -> 67.73%`，推理提速 33.4%）。
   - 下一步可直接基于 **`ckpt-68` 开展 Stage 2 RL（GRPO / OPD）** 重点拉升多轮执行/状态一致性、拒调边界精度以及缺工具后恢复调用能力；若需同步准备独立 User Simulator，可开启 `τ²-Bench Telecom`（完全域外）与 `Retail/Airline`（同域）验证多轮真实交互闭环。
