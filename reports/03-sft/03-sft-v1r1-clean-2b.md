# Qwen3.5-2B SFT-v1r1-clean：Smoke 与正式训练

实验日期：2026-11-24（Asia/Shanghai；run ID 中的时间为 UTC）。

## 实验设计

- Smoke、正式训练均从同一 Qwen3.5-2B 底座独立开始。LoRA `r=64`、`alpha=128`、dropout 0.05、all-linear，峰值学习率 `1.5e-4`，cosine、5% warmup，seed 42，BF16、8K BFD packing、padding-free，微批次 1 × 累积 8，开启梯度重计算。Smoke 一轮，正式两轮。
- 数据是 [清洗审计后冻结的版本](../02-data-audit/03-sft-v1r1-clean-audit.md)，不回填未证实的合成负例。验证集按规范化用户轮、原签名和来源 ID 与两训练集隔离；这三项检查不等同于语义级零重复。
- 正式 checkpoint 仅以清洗验证集最低 `eval_loss` 选择，不以 BFCL 或 API-Bank 选优。对照 [64K 基线](../01-baseline/01-baseline-report.md)：vLLM 0.19.1、Qwen3.5 官方推理外层、语言模式、相同 `qwen3_coder`、关思考、temperature 0、最多 1024 输出 token、300 s 超时；BFCL 并发 128、API-Bank 96。

## 两个 checkpoint 的快评方案

- 单卡依次合并、部署与评估两个已落盘 adapter；原目录不覆盖。服务每次通过结构化调用和 tool response 后收尾探针，评完释放 GPU。
- 两份权重都跑与 Clean Smoke 一模一样的 BFCL 九类 2,724 题；另外跑 API-Bank full（1,281 步：753 个调用、528 个回复），以很少的新增耗时检查调用准确率、回包后误调、回应质量。没有跑 BFCL core。
- 对照基座和 Clean Smoke，分开报告 `irrelevance/live_irrelevance`、四个调用类和三项多轮；比较实际结构化误调、缺工具补齐后的漏调，单列请求失败与截断。把 Smoke 四条线（76% / 66% / 85% / 88%）当作筛选参照，不用子集微平均掩盖弱项。验证 loss 只作为辅助信号。
- 这是 checkpoint 快筛。若据此选权重，后续 BFCL core 要把快筛内九类与未参加选优的八类分开汇报；API-Bank 已参加此次比较，不再是独立验收。

快评会话 `eval-sft-v1r1-clean-2b-quick`，远端产物 `runs/train/sft-v1r1-clean-pipeline-20261124T131742Z/`。

- **真实误调与漏调发生此消彼长。** 两个拒调类中，137 的 73 + 313 个失败、274 的 36 + 183 个失败均逐题对应 HTTP `finish_reason=tool_calls`，不是请求异常或评分器误判。274 的 `simple_python` 有 39 个调用数量错误，全部是 **零调用**（137 仅 1 个数量错误，实际多调）。API-Bank 应调用轮的 `missing_tool_call` 为基座 28、137 的 40、274 的 93。工具回包后文本泄漏和应调用轮漏调是不同指标。
- 两个正式 checkpoint 在三个多轮项都没追上基座。缺工具仍只有 4/200 和 2/200；首个判错为应调用轮无结构化调用的有 117/200 和 118/200，基座 91/200。274 的 `multi_turn_base` 也从基座 59/200 降到 30/200，主要是状态或执行结果不匹配。
- 两个 checkpoint 的 BFCL 分别 7,985 / 7,928 次请求，均 0 请求失败、0 上下文拒绝，6 / 8 次命中输出上限，耗时 278.81 / 269.78 s。API-Bank 各 1,281 次请求，均无失败、拒绝和截断，耗时 57.03 / 49.29 s。基座九类微平均从 BFCL core 对应组重算，并非 core 官方加权分。
- **结论：不把任何一份提升为通用最佳。** 137 更适合看单轮调用能力与 API-Bank 持平，但双拒调退化；274 更适合拒调专项复验，但漏调和多轮代价明显。只有 Clean Smoke 同时达到四条线，值得留做后续对照；API-Bank 补测见下节。两点和一次随机种子只能说明本次轨迹呈现调用倾向变化，不足以把原因归给训练轮数或负例占比中的某一个。下一轮优先做成对的「无关拒调 / 工具适用必须调用 / 缺参后补齐 / 缺工具后补齐」，并同时监控漏调与误调，而不是只按验证 loss 或九类微平均选模型。
