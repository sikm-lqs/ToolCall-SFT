## 3. 核心结论与机制分析

1. **降秩 (`r=16`) 对训练速度影响极小，但显著改变了能力权衡结构**
   - 训练耗时仅快 27 秒（1.7%），但低秩容量带来了明显不同的「能力侧重」：**单步工具调用 & API-Bank 更强，多轮状态保持 & 拒调容量偏弱**。

2. **`r=16` 的两大惊喜：刷新 API-Bank 历史最高记录（`70.12%`）+ 更强单轮峰值**
   - `r=16` 五个权重在 API-Bank 全部跑出 **`68.92%–70.12%`**，全面碾压 `r=64`（66.80%–68.26%）与基座（66.53%），尤其 **`L3` 最高冲至 `65.71%`**（比基座高 `+10.2 pp`），`missing_tool_call` 长期压在 15–30 次，证明低秩微调没有伤害底座在多候选工具检索和连续 API 调用上的原有能力。
   - 在 `r=16 ckpt-68` 上，`simple_python`（`90.50%`）、`multiple`（`94.00%`）、`parallel`（`89.00%`）均创 `sft-v3` 新高，且 `miss_func` 在后期还能维持 `2.5%–6.5%`（不像 `r=64` 后期塌到 `0.5%–1.0%`）。

3. **`r=16` 的两处明确短板：多轮 `base/miss_param` 掉 4–6 分、BFCL 四线全程未齐达标**
   - **`multi_turn_base` 与 `miss_param` 显著逊于 `r=64`**：`r=16` 的 `multi_turn_base` 全程只在 `22.0%–24.0%`（`r=64` 稳定在 `26.5%–30.5%`），`miss_param` 全程 `13.0%–15.0%`（`r=64` 为 `16.0%–18.5%`）。原因在于长多轮轨迹的复杂状态转换需要足够的适配器秩容量去消化，4 倍缩减后的 `r=16` 容量吃紧，优先把梯度分配给了更容易拟合的单步调用格式与文本响应。
   - **四条行为门槛线全程 0 次 4/4 全过**：`r=16 ckpt-68` 在双拒调上刚好差一点没过（`75.42% < 76%`、`63.12% < 66%`）；到 `ckpt-102..168` 拒调过线时，`simple_python` 同样掉出 `≥88%` 门槛（出现 45–68 题零调用误拒），且 `parallel` 跌回 `82.5%–84.5%`（`< 85%`）。
   - **重要警示**：这也印证了即便 `r=16` 的 `eval_loss` 在第 168 步看似还在降（`0.33921`），**第 2 轮零调用漂移依然发生了**——说明第 2 轮过拟合单工具边界是 **`sft_v3` 单工具边界分布偏斜 + 多轮遍历** 导致的，靠减小 LoRA 秩只能略微减轻（168 步零调用 `56` vs `70`），无法根治。

## 4. 对 GRPO 起始权重选型的直接建议

结合 [08-grpo方案与数据设计.md](../../docs/08-grpo方案与数据设计.md) 的规划，在 **`r=64 ckpt-68`** 与 **`r=16 ckpt-68`** 之间做客观推荐：

| 对比维度 | **`r=64 checkpoint-68`** （推荐作为 GRPO 起点） | `r=16 checkpoint-68` |
| --- | --- | --- |
| **BFCL 四线门槛** | **4/4 全通过**（`77.9% / 67.5% / 86.5% / 89.25%`） | 2/4 通过（拒调差 1–3 pp） |
| **BFCL 多轮底盘** | **`multi_turn_base 27.5%`、`miss_param 17.5%`** | `multi_turn_base 23.5%`、`miss_param 14.5%` |
| **单轮 + API-Bank** | 单轮 `86.0%–92.5%`；API-Bank `67.99%` | **单轮 `85.5%–94.0%`；API-Bank `70.12%`** |
| **BFCL Core 全量泛化** | **已实测通过（`65.71%` 微平均 / `simple_java 59%`）** | 未测 Core |

**推荐结论**：**选 `r=64 checkpoint-68`（merge 进 2B 底座后挂新 LoRA）作为 Stage 2 GRPO 起始权重**。原因很直接——我们 Phase 1 GRPO 采用的是静态单轮/多轮切片，核心擅长把 `irrelevance` / `simple_python` / `miss_func` 恢复 / 回包泄漏拉上去，但很难凭单步切片去补回 `r=16` 已经损失的 4 个百分点 `multi_turn_base` 复杂状态能力；而 `r=64 ckpt-68` 本身多轮底盘扎实、四线全过，正好交给 GRPO 补齐它的短板（`miss_func`、`API-Bank` 文本泄漏和拒调精度）。
