# 2. 基线评测

**状态：待人工审核，尚未开跑。** 目标是在同一张 A100 40GB 上，为未微调、未量化的 Qwen3.5-2B 与 Qwen3.5-0.8B 建立工具调用质量和性能基线。先通过[双模型 smoke](0-服务器环境安装.md#6-双模型-smoke-验收)，再批准下表参数。两款模型除权重外使用同一协议；历史结果不并入本次基线。

## 1. 全量矩阵

每行分别对 **2B、0.8B** 各跑一遍，共 **6 次**评测。

| 评测集 | 固定范围 | 主质量指标及附带记录 |
| --- | --- | --- |
| BFCL V4 | `bfcl-eval==2026.3.23`，`full`；Non-live、Live、Multi-turn、Memory、Web Search；不按类别或 ID 筛选 | 官方加权总分、各类别分数与分母、microaccuracy；保留 `score/` 官方 CSV |
| API-Bank | `full`；314 段参考对话，753 个调用步骤、528 个回复步骤；数据与检索版本见 [`api-bank.yaml`](../configs/eval/api-bank.yaml) | 调用正确率与分层分母、L2 工具覆盖率和条件准确率、回复 ROUGE-L；保留离线回放与参考历史口径 |
| τ²-Bench | `v0.2.0` 固定提交，`full`；Retail 114、Airline 50、Telecom 114，共 278 个默认任务，每题一次；不使用 `--limit` 或 `--task-ids` | 各域成功率 / `pass_hat_1`、平均奖励、终止原因与轨迹；总体为域成功率算术平均，不是按任务数加权 |

BFCL 的真正 `full` 需要 `SERPAPI_API_KEY`、外网和足够配额。若未获批或不可用，记为「全量阻塞」；获批后可另跑 `no-web`（4,906 道计分题，不含 Web，另有 Memory 初始化），但不得当作 `full`，也不与全量官方分数横比。两模型如需比较，应使用相同范围、同一短时间窗口，并记录 Web Search 的服务状态和时间。

## 2. 待审核参数

这些是候选实验设置，不是已经证实的最优值。使用服务器文档里的启动命令；若修改参数，应更新审核记录并在两模型上重复 smoke 或小规模试运行。

| 层级 | 参数 | 候选值与定义 |
| --- | --- | --- |
| 主机与环境 | GPU / 进程排布 | 单张 A100 40GB；单实例、单模型、单套评测串行；不同时训练或跑其他 GPU 任务 |
| 主机与环境 | vLLM / CUDA / 驱动 | `0.19.1` / `cu129`；记录实际 driver、compat 包状态、Torch、Python、GPU UUID 和包清单 |
| 权重与模板 | 模型、revision、tokenizer/chat template | 两个 ModelScope 本地快照；分别记录上游提交（若可得）、快照真实路径及文件 SHA-256；使用各自随权重提供的 tokenizer / 原始聊天模板，不手动改写 |
| 服务 | 网络 / TP / 精度 | `127.0.0.1:18003`，TP `1`，BF16，不量化，`--language-model-only`，不做 CPU offload 或 speculative decoding |
| 服务 | 显存预算 / 上下文 | `--gpu-memory-utilization 0.85`；`--max-model-len 32768`，包含 prompt 与生成；KV cache dtype `auto`，关闭 prefix cache |
| 服务 | 连续批处理 | `--max-num-seqs 128`、`--max-num-batched-tokens 8192`；其余调度、chunked prefill、编译/CUDA graph 使用该版引擎默认，留存实际启动日志 |
| 服务与生成 | 工具协议 | Native FC；启用 auto tool choice，解析器 `qwen3_coder`，不设置额外 reasoning parser；受测模型 `enable_thinking=false` |
| 服务与生成 | 解码与上限 | `--generation-config vllm`、服务 seed `0`；请求温度 `0`，每次生成上限 `1024` token，请求超时 `180s`；top-p/top-k、惩罚、stop 等不由当前 CLI 覆盖，采用引擎默认；不把服务 seed 当成逐请求种子 |
| BFCL、API-Bank | 客户端并发 | 并发 `96`，分别代表 BFCL 线程和 API-Bank worker 上限，不等于 vLLM 实际运行序列数；先核对排队、显存与错误 |
| τ² | 客户端并发 / 试验 | 同时 `3` 个模拟；各域顺序执行；场景 seed `300`、每题 `1` 次、每段最多 `200` 步 |
| τ² | 用户模拟器 | **待审核填写**独立的 OpenAI 兼容端点、模型 ID、固定版本和模板；两模型完全相同，放在另一台服务上；用户温度 `0`、生成上限同为 `1024`，记录其实际采样设置。禁止退回受测模型自模拟 |
| 重复与预热 | 顺序 / 重复 / 预热 | 2B → 0.8B；每个模型内 BFCL → API-Bank → τ²；每组合先做 1 次完整运行；切换模型后执行相同的固定结构化调用探针，预热不计入评测耗时；失败走独立重跑，不挑最好的一次 |
| 观测 | GPU / 服务指标 | 同机 `--gpu-index 0`（先确认 NVML 索引）；现有采样每轮完成后等 `0.5s`，`/metrics` 请求延迟会拉长周期；核对采样覆盖，另留服务空闲基线、启动峰值（若单独采样）及 `/metrics` 前后快照 |

人工签核：`审核人 ____ / 时间与时区 ____ / Git 提交 ____ / 参数表版本 ____ / 2B 和 0.8B 的 smoke 路径 ____ / 用户模拟器及版本 ____ / Web Search 配额 ____ / GPU 时间预算 ____ / 偏差及理由 ____`。如果 96 路出现明显压力，先记录对比小样本结果和替代并发，重新审核，不能只为某个模型临时降并发后当作同配置比较。

## 3. 审核后执行

在目标服务器的仓库根目录执行。每次只启动一个模型，完成三个评测后再切换。把 `CHECKPOINT_REVISION` 设置成此次权重确认的上游提交；若只有本地权重，写入快照清单的 SHA-256 标识。通过环境变量提供 `SERPAPI_API_KEY` 和独立模拟器的 `TOOLCALL_USER_API_KEY`（需要时），提前登录 SwanLab；不把密钥写到文件和日志。先保存实际服务命令、服务日志路径、包清单、模型文件校验和及空载显存。

下面是单模型的命令。先按[安装文档](0-服务器环境安装.md#启动一个模型)在另一个 shell 启动该模型并确认预热通过；再在评测 shell 设置 `CHECKPOINT_REVISION`、`TAU2_USER_MODEL`、`TAU2_USER_BASE_URL` 后执行。切换到 0.8B 时同步修改服务、`model` 和 `CHECKPOINT_REVISION`，不改其他设置。

```bash
model=Qwen/Qwen3.5-2B
base_url=http://127.0.0.1:18003/v1
: "${CHECKPOINT_REVISION:?填入对应模型的提交或快照清单哈希}"
: "${SERPAPI_API_KEY:?BFCL full 需要 Web Search 凭据}"
: "${TAU2_USER_MODEL:?填入已审核的独立用户模拟器模型名}"
: "${TAU2_USER_BASE_URL:?填入已审核的独立模拟器 /v1 地址}"

common=(--profile full --model "$model" --base-url "$base_url" --variant baseline
  --checkpoint-revision "$CHECKPOINT_REVISION" --gpu-index 0
  --max-tokens 1024 --temperature 0 --timeout 180)
```

以下命令逐条执行，每次检查结果再继续：

```bash
.venv/bin/toolcall-eval bfcl-v4 "${common[@]}" --concurrency 96
```

```bash
.venv/bin/toolcall-eval api-bank "${common[@]}" --concurrency 96
```

```bash
.venv/bin/toolcall-eval tau2 "${common[@]}" --concurrency 3 \
  --domains retail airline telecom --trials 1 --max-steps 200 --seed 300 \
  --user-model "$TAU2_USER_MODEL" --user-base-url "$TAU2_USER_BASE_URL" --user-temperature 0
```

即使 CLI 退出 `0` 也要检查 `summary.json` 的 `status` 与覆盖数。CLI 打印 `Run directory:`；务必写入审核记录。任何超时、上下文拒绝、OOM、抢占、截停或 SwanLab 同步错误都要保留并解释：`failed` 或 `completed_with_request_errors` 不得标为无请求错误的基线。截停是模型在预算下的结果，不静默丢弃；如需改上限，另开对照运行。停跑或重试用新目录，保留失败运行并链接到成功重跑。

## 4. 记录与验收

每个运行目录保留自动生成的文件，再补 `run-notes.md`。可将同一服务实例的 `vllm.log`、依赖和硬件快照保存在 `runs/services/`，在每个运行的备注中写明其路径。复制到远端归档时同时带走两边文件，避免只留下一个失效链接。

记录快照时，可从模型目录生成相对路径校验清单。将 `snapshot` 与 `service_dir` 设为本次实际使用的目录，在仓库根目录执行；清单的哈希可用作 `CHECKPOINT_REVISION`。

```bash
(cd "$snapshot" && find -L . -type f -print0 | LC_ALL=C sort -z | xargs -0 -r sha256sum) \
  > "$service_dir/model-sha256.txt"
sha256sum "$service_dir/model-sha256.txt"
git rev-parse HEAD
git status --short
nvidia-smi --query-gpu=timestamp,index,uuid,driver_version,memory.used,memory.total --format=csv
```

| 记录项 | 数据源与口径 |
| --- | --- |
| 可复现信息 | `config.json` + `run-notes.md`：审核版本、仓库提交/是否 clean、权重和模板 SHA-256、真实 CLI 和服务命令（无密钥）、worker 与 vLLM 包清单、GPU UUID/驱动、独立模拟器版本、预热方式/顺序、工具数据提交或版本 |
| 覆盖与质量 | `summary.json`、`metrics.json`、每题预测/评分或轨迹；保留各子集样本量、分母、得分和失败分类，不只留总分或图表 |
| 时间 | 人工记录启动、ready、预热、评测开始及结束时间（含时区）。`wall_seconds` 是 worker 及其准备/生成/评分的经过时间，不含 vLLM 启动、预热及事后画图上传；另存 BFCL `generation_seconds` / `scoring_seconds`、API-Bank `generation_seconds`、τ² `simulation_seconds` |
| 显存与压力 | `resources.jsonl`：空载 MiB、运行采样峰值 `peak_gpu_used_mib`、GPU 利用率峰值、KV cache 使用峰值、排队/在跑请求峰值、抢占增量及 OOM。整卡峰值包含 vLLM 预分配和其他进程，不等于模型权重大小；vLLM `kv_cache_usage_perc` 原值为 0–1，展示百分比时乘 100 |
| 吞吐与延迟 | 请求原始记录（BFCL / τ² 为 `model-requests.jsonl`，API-Bank 为 `predictions.jsonl`）与 `summary.json`：成功请求的输入/输出 token 总数、输出 tok/s、总 tok/s、成功请求延迟 P95。分母：BFCL 和 API-Bank 用各自生成阶段耗时，τ² 用整个模拟阶段耗时；另按 `wall_seconds` 计算端到端吞吐，分列展示。τ² 比较受测模型时使用 `agent_` 前缀指标，整体指标含模拟器流量 |
| 异常与缺测 | 请求成功/错误数、上下文拒绝、`length` 截停、到 token 上限的截停数/比例、τ² 终止原因、重跑链接、上传状态。采样或 token usage 缺失标 `N/A`，不当成 0；不把整段请求延迟当成 TTFT |

建议每次追加一行结果，空白表示尚未跑（不要预填估算值）：

```text
模型 | 数据集/范围 | run_id | 状态 | 正确数/总数或主分 | worker 秒 | 生成/模拟秒 | 空闲/峰值 MiB | KV 峰值 % | 排队峰值/抢占 | 输出/总 tok/s | P95 秒 | 错误/上下文拒绝/截停 | 备注
```

基线完成条件：6 个运行均能追溯到批准的配置；核对完整覆盖、有效遥测和已解释的异常；把两模型逐数据集并排比较。之后调并发、上下文或生成上限时，每次优先只改一个变量，用相同题集、模型快照和分母与基线比较。
