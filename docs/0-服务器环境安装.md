# 0. 服务器环境安装

目标：在单张 **A100-SXM4-40GB** 上部署 vLLM，复用已有模型缓存，分别验收 Qwen3.5-2B 和 Qwen3.5-0.8B。按第 2–6 节完成基线准备；第 7 节训练环境可跳过。以下是部署步骤，不代表 A100 已通过验收。

## 1. 环境一览

共 **6 个虚拟环境**，基线使用其中 **5 个**。Ubuntu 的 Python 3.10 保留给系统；uv 托管的 Python 3.11.18 只用来创建环境，不往基础解释器装 Torch。两个模型共用同一个推理环境，轮流启动。

| 环境 | 用途与主要依赖 | 下载源 |
| --- | --- | --- |
| `.venv` | 项目 CLI、ModelScope、SwanLab、PyYAML、Matplotlib、NVML | 清华 PyPI；已装，先检查 |
| `runs/envs/serve` | vLLM `0.19.1` + 匹配的 `cu129` Torch；负责 GPU 推理 | 普通包优先清华；Torch 用 `cu129` 专用源 |
| `runs/tools/bfcl` | BFCL 评分、Memory 检索编码器；`sentence-transformers` + CPU Torch | 普通包走清华；编码器可用 HF 镜像 |
| `runs/tools/api-bank` | API-Bank 评分、ROUGE、NLTK、检索编码器；CPU Torch | 普通包走清华；编码器可用 HF 镜像，数据 JSON 仍直连 HF |
| `runs/tools/tau2` | τ²-Bench 和 LiteLLM；调用模型服务，无需专门预装 Torch | 普通包走清华；固定版本源码从 GitHub 获取 |
| `runs/envs/train` | `cu124` Torch、Transformers、TRL、PEFT；仅用于后续训练 | 普通包走清华；Torch 用 `cu124` 专用源；已装，基线不动 |

**镜像优先，官方源兜底。** 换源只换下载地址，不换包版本、CUDA 构建或数据提交。不使用同时混入多个普通 PyPI 源的方式碰运气。显式选 `--torch-backend=cu129` 时，更换普通 PyPI 源不会连带改变 Torch 源。[清华镜像](https://mirrors.tuna.tsinghua.edu.cn/help/pypi/) · [uv 的 PyTorch 源选择](https://docs.astral.sh/uv/guides/integration/pytorch/)

## 2. 服务器预检

已知快照：Ubuntu 22.04.3 x86_64，A100 40GB（计算能力 8.0），驱动 `550.127.05`，uv `0.13.9`，磁盘约 133 GB 可用。进入仓库根目录，同一账号执行下文命令；需要时补齐 `git`、`curl`、`jq` 和 `ca-certificates`。

```bash
export PATH="$HOME/.local/bin:$PATH"
git rev-parse HEAD
uv --version
uv python find --managed-python 3.11.18
df -h . "$HOME"
nvidia-smi --query-gpu=index,uuid,name,driver_version,memory.total,compute_cap --format=csv
ss -ltn '( sport = :18003 )'
```

**通过条件：** 确认是 A100、端口 `18003` 未被占用，且无其他任务争用 GPU。`nvidia-smi` 显示 CUDA 12.4 是驱动能力，不是已装 Toolkit；缺 `nvcc` 不要求先装整套 Toolkit。A100 的架构满足所选 vLLM 的要求，但 R550 与 `cu129` 的运行兼容性仍须单独验证。[vLLM GPU 安装](https://docs.vllm.ai/en/v0.19.1/getting_started/installation/gpu/)

## 3. 主环境与模型

先验收已有环境：`.venv/bin/python --version` 应为 `3.11.18`，`uv pip check --python .venv/bin/python` 与 `.venv/bin/toolcall-eval --help` 均应成功。仅在缺失或需要修复时执行：

```bash
uv python find --managed-python 3.11.18 || uv python install 3.11.18
test -x .venv/bin/python || uv venv --python 3.11.18 .venv
uv pip install --python .venv/bin/python --default-index https://pypi.tuna.tsinghua.edu.cn/simple \
  -e . 'modelscope==1.40.3' 'swanlab==0.10.6' 'pyyaml==6.0.4' \
  'matplotlib==3.11.2' 'nvidia-ml-py==13.615.71'
```

复用 `$HOME/.cache/modelscope/models/Qwen--Qwen3.5-{2B,0.8B}/snapshots/master` 下两个快照。确认 `config.json`、权重、tokenizer 和聊天模板可读；换账号时使用可读的绝对路径，不放开 `/root` 的权限。缺失才下载，以命令输出的路径为准：

```bash
.venv/bin/toolcall-download configs/models/qwen35_2b.yaml configs/models/qwen35_0_8b.yaml
```

`master` 可变。正式评测前记录实际快照和校验和，基线期间不更新权重。

## 4. 推理环境与服务

### 安装并验证 CUDA

```bash
test -x runs/envs/serve/bin/python || uv venv --python 3.11.18 runs/envs/serve
uv pip install --python runs/envs/serve/bin/python \
  --default-index https://pypi.tuna.tsinghua.edu.cn/simple \
  --torch-backend=cu129 --only-binary vllm 'vllm==0.19.1'
uv pip check --python runs/envs/serve/bin/python
uv pip freeze --python runs/envs/serve/bin/python > runs/envs/serve-packages.txt
```

清华缺匹配 wheel 或同步异常时，只把 `--default-index` 改为 `https://pypi.org/simple`。若慢的是 Torch 下载，可先核对[阿里云 PyTorch 镜像](https://developer.aliyun.com/mirror/pytorch-wheels/)是否有同版本、同构建的 `cu129` wheel；不要拿训练用 `cu124` 顶替，也不转源码编译。

**R550 注意事项：** 先确认云商允许 CUDA 前向兼容，且已启用 NVIDIA 官方 APT 仓库。仅在此条件满足时安装兼容库，并只在推理 shell 设置变量（root 下省略 `sudo`）：

```bash
apt-cache policy cuda-compat-12-9
sudo apt-get install cuda-compat-12-9
test -r /usr/local/cuda-12.9/compat/libcuda.so.1
export VLLM_ENABLE_CUDA_COMPATIBILITY=1
export VLLM_CUDA_COMPATIBILITY_PATH=/usr/local/cuda-12.9/compat
```

云商不支持、APT 无候选或后续出现 PTX / driver mismatch 时，优先换用云商提供的原生 CUDA 12.9 驱动镜像（12.9 GA 对应 Linux 驱动 `575.51.03` 或更高），新开 shell，不带上述变量重验；不要在租用实例上自行卸载驱动。[NVIDIA CUDA 12.9 说明](https://docs.nvidia.com/cuda/archive/12.9.0/cuda-toolkit-release-notes/index.html) · [vLLM 兼容库说明](https://docs.vllm.ai/en/v0.19.1/usage/troubleshooting/)

```bash
runs/envs/serve/bin/python - <<'PY'
import vllm
import torch

assert vllm.__version__ == '0.19.1', vllm.__version__
assert torch.cuda.is_available() and torch.version.cuda == '12.9', torch.version.cuda
assert torch.cuda.get_device_capability(0) == (8, 0)
assert torch.cuda.is_bf16_supported()
matrix = torch.ones((32, 32), device='cuda', dtype=torch.bfloat16)
assert (matrix @ matrix)[0, 0].item() == 32
print(vllm.__version__, torch.__version__, torch.cuda.get_device_name(0))
PY
```

**通过条件：** 依赖检查、GPU 识别和 BF16 实算均成功；服务加载与工具调用还需通过第 6 节。

### 启动一个模型

在推理 shell 执行；`model` 换为 `Qwen/Qwen3.5-0.8B` 即可切换到另一份默认快照。不同缓存位置需改 `snapshot`。一次只起一个模型，切换前 `Ctrl+C` 停旧实例，确认端口与显存释放。不向公网开放 `18003`。

```bash
set -o pipefail
model=Qwen/Qwen3.5-2B
snapshot="$HOME/.cache/modelscope/models/Qwen--${model#*/}/snapshots/master"
model_slug="${model#*/}"
service_dir="runs/services/${model_slug,,}/$(date -u +%Y%m%dT%H%M%S.%NZ)"
mkdir -p "$service_dir"

runs/envs/serve/bin/vllm serve "$snapshot" --served-model-name "$model" \
  --host 127.0.0.1 --port 18003 --tensor-parallel-size 1 --dtype bfloat16 \
  --language-model-only --max-model-len 32768 --gpu-memory-utilization 0.85 \
  --max-num-seqs 128 --max-num-batched-tokens 8192 \
  --enable-auto-tool-choice --tool-call-parser qwen3_coder \
  --generation-config vllm --seed 0 --no-enable-prefix-caching \
  2>&1 | tee "$service_dir/vllm.log"
```

这组参数只作为 smoke 和[基线审核](2-基线评测.md#2-待审核参数)的起点，不代表高并发已验收。`32768` 用于给 τ² 多轮上下文留余量，仍要检查实际拒绝和截停。

## 5. 评测 worker

在**另一个评测 shell**执行，不带推理的兼容变量。BFCL 和 API-Bank 先装同一份 **CPU Torch wheel**，再运行各自的 `prepare`，避免解析到 CUDA 大包。`2.6.0+cpu` 是候选；如果依赖检查失败，先查冲突，不解除约束盲目重试。

```bash
(
  set -e
  export PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
  wheel_dir="$PWD/runs/wheels"
  cpu_index=https://download.pytorch.org/whl/cpu
  mkdir -p "$wheel_dir"
  for worker in bfcl api-bank; do
    test -x "runs/tools/$worker/bin/python" || \
      uv venv --python 3.11.18 --seed --default-index "$PIP_INDEX_URL" "runs/tools/$worker"
  done
  runs/tools/bfcl/bin/python -m pip download --no-deps --only-binary=:all: \
    --index-url "$cpu_index" --dest "$wheel_dir" 'torch==2.6.0+cpu'
  printf '%s\n' 'torch==2.6.0+cpu' > "$wheel_dir/cpu-torch.txt"
  for worker in bfcl api-bank; do
    worker_python="runs/tools/$worker/bin/python"
    "$worker_python" -m pip install --find-links "$wheel_dir" 'torch==2.6.0+cpu'
  done
  PIP_CONSTRAINT="$wheel_dir/cpu-torch.txt" .venv/bin/toolcall-eval prepare bfcl-v4
  PIP_CONSTRAINT="$wheel_dir/cpu-torch.txt" .venv/bin/toolcall-eval prepare api-bank
  .venv/bin/toolcall-eval prepare tau2
  for worker in bfcl api-bank tau2; do
    "runs/tools/$worker/bin/python" -m pip check
  done
  for worker in bfcl api-bank; do
    "runs/tools/$worker/bin/python" -c 'import torch, sentence_transformers; assert torch.version.cuda is None; print(torch.__version__)'
  done
)
```

- **下载慢：** 确认阿里云有同版本 CPU wheel 后可替换 `cpu_index`，或预先把匹配 wheel 放入 `runs/wheels/` 并跳过 `pip download`。普通包镜像缺件时仅对该次操作改回官方 PyPI，保留约束。
- **HF 超时：** 编码器可在评测 shell 设置 `HF_ENDPOINT=https://hf-mirror.com` 后重试，仅用于公共资产，不向镜像发送私有凭据。API-Bank 的三份固定 revision JSON **不读 `HF_ENDPOINT`，且 `prepare` 会重新下载**；只预放文件不能跳过直连。直连失败时先解决网络或更改下载入口，再验收，不把数据不全当作就绪。
- **通过条件：** 三个 `prepare` 和 `pip check` 均成功；两个编码器环境均可导入 `sentence_transformers`，并报告 CPU Torch。已有 worker 先按此检查，合格则不用重装。

## 6. 双模型 smoke 验收

首次先执行 `.venv/bin/swanlab login`。每次服务启动后，在评测 shell 把 `model` 设为当前模型并执行；无需远程模拟器密钥即可跑这轮链路检查。

```bash
(
  set -e -o pipefail
  model=Qwen/Qwen3.5-2B
  host=http://127.0.0.1:18003
  curl -fsS --noproxy '*' --max-time 10 "$host/health"
  curl -fsS --noproxy '*' --max-time 10 "$host/v1/models" \
    | jq -e --arg model "$model" '.data | any(.id == $model)'
  jq -n --arg model "$model" '{model: $model,
    messages: [{role: "user", content: "Call lookup_city for Paris."}],
    tools: [{type: "function", function: {name: "lookup_city", description: "Look up a city",
      parameters: {type: "object", properties: {city: {type: "string"}}, required: ["city"]}}}],
    tool_choice: "auto", chat_template_kwargs: {enable_thinking: false}, temperature: 0, max_tokens: 256}' \
    | curl -fsS --noproxy '*' --max-time 180 "$host/v1/chat/completions" \
        -H 'Content-Type: application/json' --data-binary @- \
    | jq -e '.choices[0].message.tool_calls | any(.function.name == "lookup_city" and
        (.function.arguments | fromjson | .city == "Paris"))'
  for suite in bfcl-v4 api-bank tau2; do
    .venv/bin/toolcall-eval "$suite" --profile smoke --model "$model" \
      --base-url "$host/v1" --concurrency 1 --gpu-index 0
  done
)
```

**放行清单（两个模型都要满足）：**

- [ ] `/health` 成功，`/v1/models` 返回当前模型，工具探针返回 `true`（只验证调用结构，不执行工具）。
- [ ] 三个 `summary.json` 都是 `completed`：BFCL 3 题、API-Bank 100 步、τ² Retail 2 题；保留预测或轨迹、日志和显存遥测。确认无请求错误、上下文拒绝或 OOM，记录低分、截停及终止原因；smoke 不设分数门槛。
- [ ] 保存六个运行目录和对应 `vllm.log`。τ² 自模拟只用于 smoke；[正式基线](2-基线评测.md)须审核参数、固定独立顾客模拟器并验证其接口，再启动全量。未满足验收项则先查 `vllm.log` 和 `benchmark.log`，不要进入全量。

已有 `runs/envs/train/` 直接复用。仅在重建时运行以下命令；不要在推理兼容变量生效的 shell 中验证训练栈。
