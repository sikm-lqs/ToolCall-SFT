# 0. 服务器环境安装

目标：在单张 **NVIDIA A100-SXM4-40GB** 上，隔离项目、训练、推理和各评测 worker 环境，使用本地权重启动 vLLM，并分别验收 Qwen3.5-2B 和 Qwen3.5-0.8B。以下配置基于用户提供的检测快照，**不代表 vLLM 或 smoke 已在 A100 上验收**。

## 1. 现状与预检

| 项目 | 检测值 |
| --- | --- |
| 系统 | Ubuntu 22.04.3 LTS，`6.2.0-37-generic`，x86_64 |
| CPU / 内存 / 磁盘 | Intel Xeon Platinum 8575C，16 核；31 GB；`/dev/vda3` 共 196 GB、可用 133 GB |
| GPU | A100-SXM4-40GB，40960 MiB，计算能力 8.0；驱动 `550.127.05`，`nvidia-smi` 显示 CUDA 12.4 |
| 工具链 | `/usr/bin/python3.10` 为 3.10.12；uv 0.13.9，托管 Python 3.11.18（`/root/.local/share/uv/python/`）；无 conda、无 `nvcc` |
| 镜像 | `~/.config/pip/pip.conf` 与 `~/.config/uv/uv.toml` 均用清华 TUNA |
| 服务 | `127.0.0.1:18003` 未运行；vLLM 待安装或核验 |

SSH 登录 A100 后，以维护项目和模型缓存的同一账号执行。`sudo` 命令在 root shell 中去掉 `sudo`；优先复用已有软件，不替换系统 Python。新机器缺少 `git`、`curl`、`ca-certificates` 或 `jq` 时由管理员用 APT 补齐。

```bash
cat /etc/os-release
uname -rm
lscpu | grep -E '^(CPU\(s\):|Model name:)'
free -h
df -h / "$HOME"
nvidia-smi --query-gpu=index,uuid,name,driver_version,memory.total,compute_cap --format=csv
nvidia-smi
command -v nvcc || true
ss -ltn '( sport = :18003 )'
```

V100 的计算能力是 7.0，低于所选 vLLM 版本的 7.5 门槛；A100 的 8.0 满足架构要求。**架构满足要求不等于驱动与 wheel 兼容。** `nvidia-smi` 的 CUDA 字样是驱动能力，不是已安装的 Toolkit；本流程先验证预编译 wheel，不因缺 `nvcc` 就安装整套 Toolkit。参见 [vLLM 0.19.1 GPU 安装](https://docs.vllm.ai/en/v0.19.1/getting_started/installation/gpu/)和 [NVIDIA CUDA 兼容性](https://docs.nvidia.com/deploy/cuda-compatibility/index.html)。

## 2. 项目主环境

只在 uv 缺失时使用 [Astral 官方安装方式](https://docs.astral.sh/uv/getting-started/installation/)；已有 uv 0.13.9 则复用。新机器可以在对应用户配置中设置 TUNA：pip 的 `[global]` 下设 `index-url = https://pypi.tuna.tsinghua.edu.cn/simple`；uv 的 `[[index]]` 下设相同的 `url` 和 `default = true`。不覆盖已有配置；GPU wheel 使用下文的显式源。

已有 checkout 直接进入仓库根目录，首次部署才执行 `git clone https://github.com/sikm-lqs/ToolCall-SFT.git`。以下命令都在仓库根目录运行。

```bash
export PATH="$HOME/.local/bin:$PATH"
uv --version
git rev-parse HEAD
uv python find --managed-python 3.11.18 || uv python install 3.11.18
test -x .venv/bin/python || uv venv --python 3.11.18 .venv
.venv/bin/python --version
# 仅在主环境缺包或需要重建时执行：
uv pip install --python .venv/bin/python -e . \
  'modelscope==1.40.3' 'swanlab==0.10.6' 'pyyaml==6.0.4' \
  'matplotlib==3.11.2' 'nvidia-ml-py==13.615.71'
uv pip check --python .venv/bin/python
.venv/bin/toolcall-eval --help
```

上述固定版本来自检测快照，并非仓库的 lockfile。如果镜像缺版本，先查源或从已有环境导出清单，不静默降级。

## 3. 复用本地模型

| 模型 | ModelScope 快照（`root` 账号） | 大小 |
| --- | --- | --- |
| `Qwen/Qwen3.5-2B` | `/root/.cache/modelscope/models/Qwen--Qwen3.5-2B/snapshots/master` | 4.3 GB |
| `Qwen/Qwen3.5-0.8B` | `/root/.cache/modelscope/models/Qwen--Qwen3.5-0.8B/snapshots/master` | 1.7 GB |

先用 `ls -lhL` 或 `du -shL` 确认权重、`config.json`、tokenizer 和聊天模板文件可读。换账号时使用该账号可读的绝对路径，或把快照放到共享磁盘，不改 `/root` 的访问权限。快照缺失才下载，使用命令实际输出的路径：

```bash
.venv/bin/toolcall-download configs/models/qwen35_2b.yaml configs/models/qwen35_0_8b.yaml
```

`master` 是可变引用。正式运行前记录上游提交（能确认时）与文件 SHA-256；不要在两款模型的基线之间更新快照。

## 4. 独立训练环境（不阻塞基线）

已有 `runs/envs/train/` 先做下方 CUDA 验证。只有缺失或需要重建才安装；不把训练环境的 Torch 用于 vLLM。仓库尚未实现训练入口。

```bash
test -x runs/envs/train/bin/python || uv venv --python 3.11.18 runs/envs/train
train_python=runs/envs/train/bin/python

```

[PyTorch 2.6.0 官方 CUDA 12.4 wheel](https://pytorch.org/get-started/previous-versions/#v260)的运行验证不需要 `nvcc`。新开 shell，不带下节的 vLLM 兼容环境变量，再运行：

runs/envs/train/bin/python - <<'PY'

## 5. 安装并验收 vLLM

候选固定为 `vLLM 0.19.1` + CUDA 12.9 wheel：仓库本地历史曾用此 vLLM 版本，**A100 的 R550 驱动路线仍需现场验收**。不执行无版本的 `uv pip install vllm`，也不把训练用 `cu124` Torch 注入推理环境。

```bash
test -x runs/envs/serve/bin/python || uv venv --python 3.11.18 runs/envs/serve
serve_python=runs/envs/serve/bin/python
uv pip install --python "$serve_python" --default-index https://pypi.org/simple \
  --torch-backend=cu129 'vllm==0.19.1'
uv pip check --python "$serve_python"
uv pip freeze --python "$serve_python" > runs/envs/serve-packages.txt
```

**现有 R550 镜像：** 先请云商确认 A100 实例允许 CUDA Forward Compatibility，并能通过官方 NVIDIA Ubuntu 22.04 软件仓库安装 `cuda-compat-12-9`。这是用户态兼容库，不是换内核驱动。NVIDIA 列出 R550 与该包的历史兼容组合；以实例实际加载和 smoke 结果为准。只在推理 shell 设置变量：

```bash
apt-cache policy cuda-compat-12-9
sudo apt-get install cuda-compat-12-9
test -r /usr/local/cuda-12.9/compat/libcuda.so.1
export VLLM_ENABLE_CUDA_COMPATIBILITY=1
export VLLM_CUDA_COMPATIBILITY_PATH=/usr/local/cuda-12.9/compat
```

如果云商不支持、APT 无候选包，或出现旧驱动、PTX/JIT、`system driver mismatch` 等错误，不用 `cu124` 强行覆盖，也不在租用实例上自行卸载驱动。优先切到云商提供的 **原生支持 CUDA 12.9 的驱动镜像**（CUDA 12.9 GA 对应 Linux 驱动不低于 `575.51.03`），新开推理 shell，不设置上述兼容变量，重新验收。参考 [NVIDIA 前向兼容矩阵（含 R550）](https://docs.nvidia.com/deploy/pdf/CUDA_Compatibility.pdf)、[CUDA 12.9 Release Notes](https://docs.nvidia.com/cuda/archive/12.9.0/cuda-toolkit-release-notes/index.html)及 [vLLM 驱动故障排查](https://docs.vllm.ai/en/v0.19.1/usage/troubleshooting/)。

```bash
runs/envs/serve/bin/python - <<'PY'
import vllm
import torch

assert torch.cuda.is_available()
assert torch.version.cuda == '12.9', torch.version.cuda
assert torch.cuda.get_device_capability(0) == (8, 0)
assert torch.cuda.is_bf16_supported()
matrix = torch.ones((32, 32), device='cuda', dtype=torch.bfloat16)
assert (matrix @ matrix)[0, 0].item() == 32
print(vllm.__version__, torch.__version__, torch.cuda.get_device_name(0))
PY
```

### 启动一个模型

在推理 shell 中运行。一次只服务一个受测模型，切换模型前 `Ctrl+C` 停止旧实例，确认端口和显存释放。下面以 2B 为例；跑 0.8B 时同时替换 `model` 和 `snapshot`。服务只监听 loopback；远程访问用 SSH 端口转发，不裸露公网端口。

```bash
set -o pipefail
model=Qwen/Qwen3.5-2B
snapshot="${HOME}/.cache/modelscope/models/Qwen--${model#*/}/snapshots/master"
model_slug="${model#*/}"
service_dir="runs/services/${model_slug,,}/$(date -u +%Y%m%dT%H%M%S.%NZ)"
mkdir -p "$service_dir"
test -r "$snapshot/config.json"

runs/envs/serve/bin/vllm serve "$snapshot" --served-model-name "$model" \
  --host 127.0.0.1 --port 18003 --tensor-parallel-size 1 --dtype bfloat16 \
  --language-model-only --max-model-len 32768 --gpu-memory-utilization 0.85 \
  --max-num-seqs 128 --max-num-batched-tokens 8192 \
  --enable-auto-tool-choice --tool-call-parser qwen3_coder \
  --generation-config vllm --seed 0 --no-enable-prefix-caching \
  2>&1 | tee "$service_dir/vllm.log"
```

这组服务参数是 smoke 起点，也是[基线审核](2-基线评测.md#2-待审核参数)的候选值，不代表已经验证 96 路并发。Qwen 的模型卡均用 `qwen3_coder` 做工具解析：[2B](https://huggingface.co/Qwen/Qwen3.5-2B)、[0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B)。

## 6. 双模型 smoke 验收

另开评测 shell，仍在仓库根目录。`prepare all` 只需在依赖齐备前执行，需访问 GitHub、PyPI、Hugging Face 等数据源；当前评测入口会上传 SwanLab，首次请先登录。

```bash
.venv/bin/toolcall-eval prepare all
.venv/bin/swanlab login
```

每次启动模型后，在评测 shell 把 `model` 设置成正在服务的模型，依次执行。探针只检查结构化调用，不会执行描述中的工具。

```bash
set -o pipefail
model=Qwen/Qwen3.5-2B
host=http://127.0.0.1:18003
base_url="$host/v1"
curl -fsS --noproxy '*' --max-time 10 "$host/health"
curl -fsS --noproxy '*' --max-time 10 "$base_url/models" \
  | jq -e --arg model "$model" '.data | any(.id == $model)'
jq -n --arg model "$model" '{model: $model,
  messages: [{role: "user", content: "Call lookup_city for Paris."}],
  tools: [{type: "function", function: {name: "lookup_city", description: "Look up a city",
    parameters: {type: "object", properties: {city: {type: "string"}}, required: ["city"]}}}],
  tool_choice: "auto", chat_template_kwargs: {enable_thinking: false}, temperature: 0, max_tokens: 256}' \
  | curl -fsS --noproxy '*' --max-time 180 "$base_url/chat/completions" \
      -H 'Content-Type: application/json' --data-binary @- \
  | jq -e '.choices[0].message.tool_calls | any(.function.name == "lookup_city" and
      (.function.arguments | fromjson | .city == "Paris"))'

for suite in bfcl-v4 api-bank tau2; do
  .venv/bin/toolcall-eval "$suite" --profile smoke --model "$model" \
    --base-url "$base_url" --concurrency 1 --gpu-index 0 || break
done
```

确认**两个模型各有三个完整 smoke**：探针为 `true`，`summary.json` 状态为 `completed`，覆盖预定样本，有原始输出和遥测，无请求错误、上下文拒绝或 OOM。Smoke 检查链路，不设准确率门槛；低分或截停仍需记录。τ² smoke 可用受测模型自模拟，但正式基线必须固定独立模拟器。曾在 `10240` 上下文遇到 τ² 拒绝，因此本轮从 `32768` 起步，仍需看实际数据。未通过则查 `vllm.log` 和 `benchmark.log`，不要进入全量。
