# 0. 服务器环境安装

目标：在单张 **NVIDIA A100-SXM4-40GB** 新租实例上，从零补齐基础系统工具、配置国内高速镜像源、使用 `uv` + Python `3.11` 搭建彼此隔离的**主调度 / 推理 / 评测 / 训练**环境，并完成 `Qwen3.5-2B` 与 `Qwen3.5-0.8B` 的服务启动和 smoke 验收。

## 1. 服务器原始环境与安装策略

### 1.1 交付状态核对

| 项目 | 服务器交付状态 | 对安装方案的影响 |
| --- | --- | --- |
| GPU | NVIDIA A100-SXM4-40GB（`sm_80`，108 SM，ECC 开，400 W） | 原生支持 BF16 / TF32，满足所有 vLLM 与训练要求 |
| 驱动 / CUDA | 驱动 `595.84`（`.run` + DKMS），最高支持 CUDA `13.2`；Toolkit `13.0.88`（`/usr/local/cuda`）；无系统级 cuDNN / NCCL / TensorRT | **原生支持 `cu128` / `cu129` / `cu130` wheel，无需 `cuda-compat`**；PyTorch 与 vLLM wheel 自带运行时库 |
| 系统与计算资源 | Ubuntu 24.04.3 LTS（内核 `7.0.0-28-generic`）；16 vCPU（Xeon 8575C）；31 GB RAM + 8 GB swap；196 GB 磁盘（已用 28 GB，约 168 GB 可用） | 磁盘需精打细算（防 checkpoint 撑爆）；31 GB 内存注意限制数据预处理并发数 |
| 编译与基础工具 | `gcc 13.3.0`、`make 4.3`；**未安装 `git`、`curl`、`jq`、`cmake`、`ninja`、`docker`、`uv`** | **必须先用 APT 补齐 `git`、`curl`、`jq`**（`assets.py` 拉取 `tau2` 和 `API-Bank` 依赖 `git`） |
| 预装 Python | `/home/vipuser/miniconda3` base（Python `3.14.7`，`pip 26.2.1`，属主 `root`）；系统 `/usr/bin/python3` 为 `3.12.3`（无 pip） | **不使用 conda base（Python 3.14 生态兼容性差且属主为 root）**，也不往系统 Python 装包 |

### 1.2 核心环境架构（5 类隔离 venv）

统一使用 `uv` 托管的 **Python 3.11** 创建虚拟环境，避免 Python 3.14/3.12 的扩展编译坑和包版本冲突：

| 环境路径 | 职责与核心依赖 | 镜像源策略 |
| --- | --- | --- |
| `.venv` | 主 CLI（`toolcall-eval` / `toolcall-download`）、ModelScope、SwanLab、PyYAML、Matplotlib、NVML | 清华 PyPI |
| `runs/envs/serve` | vLLM `0.19.1` 推理服务（原生支持 Qwen3.5 与 `qwen3_coder` 解析器） | 清华 PyPI + 上交大 `cu129` PyTorch 源 |
| `runs/envs/train` | SFT / OPD / GRPO 训练（`torch`、`transformers>=5.0`、`trl>=0.27`、`peft`、`accelerate`、`datasets`、`flash-linear-attention`） | 清华 PyPI + 上交大 `cu129` PyTorch 源 |
| `runs/tools/bfcl` | BFCL V4 评分与 Memory 检索编码器（锁 `numpy<2`，CPU Torch） | 清华 PyPI + CPU Torch + HF 镜像 |
| `runs/tools/api-bank` | API-Bank 评分、ROUGE、NLTK 与检索编码器（CPU Torch） | 清华 PyPI + CPU Torch + HF 镜像 |
| `runs/tools/tau2` | τ²-Bench 与 LiteLLM（无 Torch 依赖） | 清华 PyPI + GitHub 浅克隆 |

> **为什么训练与推理均选 `cu129`？** 宿主机驱动 `595.84` 最高支持 CUDA `13.2`，可以完美向下兼容 `cu129`；同时国内镜像（如上海交大）已同步 `cu129` 轮子且 `vllm==0.19.1` 与该构建配合最稳，后续若在同一环境或以 `vllm_mode="server"` 跑 GRPO 也方便对齐。

## 3. 安装 `uv` 并配置全套国内镜像

### 3.1 停用 conda 自动激活并独立安装 `uv`

避免登录 shell 自动进入属主为 `root` 的 conda Python 3.14 环境，直接通过系统 `pipx` 或独立包走清华源把 `uv` 装到当前用户 `~/.local/bin`：

```bash
# 通过系统 apt 安装 pipx 后，走清华 PyPI 源秒装 uv（不污染 conda 和系统 Python）

pipx ensurepath
export PATH="$HOME/.local/bin:$PATH"

which uv && uv --version
```

### 5.3 启动单个受测模型服务

在单独的终端（或 `tmux` 会话）中启动。一次只服务一个模型，切换模型前 `Ctrl+C` 停止旧进程并确认显存释放；服务仅绑定 `127.0.0.1`：

```bash

  --host 127.0.0.1 --port 18003 --tensor-parallel-size 1 --dtype bfloat16 \

  --max-num-seqs 256 --max-num-batched-tokens 32768 \
  --enable-auto-tool-choice --tool-call-parser qwen3_coder \
  --generation-config vllm --seed 0 --enable-prefix-caching \
```

## 6. 安装并验收评测 Worker（`runs/tools/`）

另开一个终端（确认 `HF_ENDPOINT=https://hf-mirror.com` 已生效）。`bfcl` 与 `api-bank` 只需要 CPU 推理检索编码器，预先固定安装 `torch==2.6.0+cpu`（走上交大 CPU wheel 源），避免误下载几个 GB 的 CUDA 版 Torch：

```bash
(
  set -e
  export PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
  wheel_dir="$PWD/runs/wheels"
  cpu_index=https://mirror.sjtu.edu.cn/pytorch-wheels/cpu
  mkdir -p "$wheel_dir"

  for worker in bfcl api-bank; do
    test -x "runs/tools/$worker/bin/python" || \
      uv venv --python 3.11 --seed "runs/tools/$worker"
  done

  runs/tools/bfcl/bin/python -m pip download --no-deps --only-binary=:all: \
    --index-url "$cpu_index" --dest "$wheel_dir" 'torch==2.6.0+cpu'
  printf '%s\n' 'torch==2.6.0+cpu' > "$wheel_dir/cpu-torch.txt"

  for worker in bfcl api-bank; do
    "runs/tools/$worker/bin/python" -m pip install --find-links "$wheel_dir" 'torch==2.6.0+cpu'
  done

  PIP_CONSTRAINT="$wheel_dir/cpu-torch.txt" .venv/bin/toolcall-eval prepare bfcl-v4
  PIP_CONSTRAINT="$wheel_dir/cpu-torch.txt" .venv/bin/toolcall-eval prepare api-bank
  .venv/bin/toolcall-eval prepare tau2

  for worker in bfcl api-bank tau2; do
    "runs/tools/$worker/bin/python" -m pip check
  done
  for worker in bfcl api-bank; do
    "runs/tools/$worker/bin/python" -c 'import torch, sentence_transformers; assert torch.version.cuda is None; print(torch.__version__)'
  done
)
```

> 若 `mirror.sjtu.edu.cn/pytorch-wheels/cpu` 缺少 `2.6.0+cpu` 或下载失败，将 `cpu_index` 替换为 `https://download.pytorch.org/whl/cpu` 重试即可。另外 API-Bank 的三份 `level-3*.json` 数据文件在 `prepare` 中直接从 HuggingFace URL 拉取（不读取 `HF_ENDPOINT`），如偶发超时可临时配代理或单独重跑 `prepare api-bank`。

## 7. 双模型 Smoke 验收

首次上报实验前执行一次 SwanLab 登录：

```bash
.venv/bin/swanlab login
```

确认第 5 节的 vLLM 服务已就绪后，在评测终端分别对 `Qwen/Qwen3.5-2B` 和 `Qwen/Qwen3.5-0.8B` 执行链路探针与 smoke：

```bash
(
  set -e -o pipefail
  model=Qwen/Qwen3.5-2B
  host=http://127.0.0.1:18003

  curl -fsS --noproxy '*' --max-time 10 "$host/health"
  curl -fsS --noproxy '*' --max-time 10 "$host/v1/models" \
    | jq -e --arg model "$model" '.data | any(.id == $model)'

  jq -n --arg model "$model" '{model: $model,
    messages: [{role: "user", content: "Call lookup_city for Paris."}],
    tools: [{type: "function", function: {name: "lookup_city", description: "Look up a city",
      parameters: {type: "object", properties: {city: {type: "string"}}, required: ["city"]}}}],
    tool_choice: "auto", chat_template_kwargs: {enable_thinking: false}, temperature: 0, max_tokens: 256}' \
    | curl -fsS --noproxy '*' --max-time 180 "$host/v1/chat/completions" \
        -H 'Content-Type: application/json' --data-binary @- \
    | jq -e '.choices[0].message.tool_calls | any(.function.name == "lookup_city" and
        (.function.arguments | fromjson | .city == "Paris"))'

  for suite in bfcl-v4 api-bank tau2; do
    .venv/bin/toolcall-eval "$suite" --profile smoke --model "$model" \
      --base-url "$host/v1" --concurrency 1 --gpu-index 0
  done
)
```

- [ ] 三个 `summary.json` 状态均为 `completed`，无 `request_errors`、无 `context_rejections`、无 OOM。
- [ ] 确认结果已写入 `runs/eval/` 并成功上传 SwanLab；正式基线参数与独立 User Simulator 要求见 [02. 基线评测](02-基线评测.md)。

## 8. 训练环境安装（`runs/envs/train`：SFT / OPD / GRPO）

本阶段用于后续开发与运行 `src/toolcall/training/`，不阻塞第 7 节的基线评测。

### 8.1 安装核心训练依赖（SFT + OPD + GRPO 基础）

在 `runs/envs/train` 中统一使用 **Python 3.11 + `cu129` PyTorch**，安装支持 Qwen3.5 的新版生态包：
- `transformers >= 5.0`：原生支持 Qwen3.5 混合架构（`Qwen3_5ForCausalLM` 等）
- `trl >= 0.27`：包含 Qwen3.5 权重映射修复，提供 `SFTTrainer`、`GKDTrainer`/`DistillationTrainer`（OPD）、`GRPOTrainer`（RL）
- `flash-linear-attention`：为 Qwen3.5 的 Gated DeltaNet 线性注意力层提供 Triton 加速核，避免回退慢速纯 PyTorch 循环

```bash
uv venv --python 3.11 runs/envs/train
train_python=runs/envs/train/bin/python

# 1. 显式钉死 cu129 版本（与 vllm==0.19.1 复用同一份 cu129 Torch 缓存，避免双源解析回退到 PyPI 默认 cu13 构建）
uv pip install --python "$train_python" \
  --index-url https://mirror.sjtu.edu.cn/pytorch-wheels/cu129/ \
  --extra-index-url https://pypi.tuna.tsinghua.edu.cn/simple \
  --index-strategy unsafe-best-match \
  'torch==2.10.0+cu129' 'torchvision==0.30.0+cu129'

# 2. 安装训练栈与 Qwen3.5 线性注意力加速（普通包自动走清华源）
uv pip install --python "$train_python" \
  'transformers>=5.0' 'trl>=0.27' 'peft>=0.14' 'accelerate>=1.0' \
  'datasets>=4.0' safetensors swanlab flash-linear-attention

uv pip check --python "$train_python"
uv pip freeze --python "$train_python" > runs/envs/train-packages.txt
```

### 8.2 GRPO 阶段与 vLLM 的两种协同模式

单卡 A100 40GB 上跑 `TRL GRPOTrainer` 时，按显存与依赖隔离需求二选一：
1. **`vllm_mode="server"`（推荐优先采用）**：由 `runs/envs/serve` 独立拉起本地 vLLM 服务，`runs/envs/train` 作为训练客户端通信，彻底隔离训练与推理依赖锁。
2. **`vllm_mode="colocate"`**：若需单进程共享显存池，可在单独的 RL 环境（如 `runs/envs/rl`）中执行 `uv pip install "trl[vllm]"`，让依赖解析器锁定匹配窗口内的 `trl` 与 `vllm` 版本。

### 8.3 验收训练环境与磁盘/内存守则

```bash
runs/envs/train/bin/python - <<'PY'
import torch
import transformers
import trl
from peft import LoraConfig
from trl import SFTTrainer, GRPOTrainer

assert torch.cuda.is_available() and torch.cuda.is_bf16_supported()
assert torch.version.cuda == '12.9', torch.version.cuda
assert torch.cuda.get_device_capability(0) == (8, 0)
assert int(transformers.__version__.split('.')[0]) >= 5
print("Torch:", torch.__version__, "CUDA:", torch.version.cuda,
      "Transformers:", transformers.__version__, "TRL:", trl.__version__,
      LoraConfig.__name__, SFTTrainer.__name__, GRPOTrainer.__name__)
PY
```

**资源使用提醒（196 GB 磁盘 / 31 GB 内存）：**
- **定期清缓存**：装完各环境后执行 `uv cache clean`，可立即释放数 GB 安装缓存；
- **控制 Checkpoint 占用**：全参微调 2B 含优化器状态的单份 checkpoint 约占 16 GB，训练配置务必开启 `save_total_limit=2` 或优先采用 BF16 + LoRA；
- **控制 CPU 并发**：数据预处理 `datasets.map(..., num_proc=4)` 即可，避免 16 核全开或把大 Teacher 模型全量 offload 到 31 GB 内存导致 OOM。
